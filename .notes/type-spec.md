## 単位（★2026-08-20 決定）

**rem。** それまで px で書いていたが、**一度も決めていなかった**（この文書にも
`handoff` にも `rem` の記述が無かった）。行内コードで `em` を使ったときに
「px か rem か」が表に出て、そこで決めた。

```
rem   font-size / line-height / 余白 / 角丸 / アイコンの寸法
px    1px の罫、焦点の輪（2px）、当たり判定（36px）、ブレークポイント
em    「まわりの文字に合わせる」ものだけ → 行内コードの1箇所のみ
```

- **理由**: ページ全体のズーム（Ctrl +）は px でも効くが、**「文字だけ大きくする」
  ブラウザ設定は px を無視する**。長文（prose）を対象にする以上ここは譲れない。
  Bootstrap 5 / Material UI / Tailwind v4 も rem に統一している
  （Tailwind v4 は `--text-sm: 0.875rem` / `--spacing: 0.25rem`、
  `em` は `letter-spacing` だけ）
- **`html` の `font-size` は触らない**。触るとユーザー設定を上書きしてしまう。
  Suisou が `font-size` を置くのは `[data-suisou-root]`（＝ body 側）だけ
- **px のまま残すもの**: 線と焦点の輪は「線」の都合、当たり判定は「指」の都合で、
  どちらも文字サイズに追従させない
- **「4の倍数」はルートが 16px のときに成立する**。設定を変えれば全体が比例して
  動くので、段どうしの関係は保たれる
- 名前の数字（`--suisou-size-14`）は**ルート 16px のときの px** を指す。
  値は `0.875rem`

## §2 前提

| # | 前提 | 理由 |
|---|---|---|
| T1 | **本文は 14px（UI）/ 16px（長文）** | wixdex・Mado とも実測で `text-sm`(14px) が最頻出。16px を主役にしていない＝密度を優先する選択が既にされていた |
| T2 | **サイズは4px グリッドに乗せる（14 のみ例外）** | 行間・余白と同じグリッドに乗せて垂直リズムを揃えるため |
| T3 | **階層はサイズだけで作らない。ウェイトと罫線を併用する** | 実測で「14px + semibold」が最頻出の見出しだった（§4）。HTML のデフォルトも h4 以下はサイズを諦めている |
| T4 | **等比スケールは採らない** | 小さい側（12〜20px）では整数への丸めが比率より支配的で、どの比率を選んでも同じ値に落ちる（§3） |

## §3 サイズスケール（確定）

```
12  14  16  20  24  28  32
```

- **14 以外はすべて4の倍数**
- 比率は 1.143〜1.25 でばらつく。**これは意図的**

### なぜ等比にしないか

**等比は整数に丸めた時点で崩れるため。**

```
ratio 1.15 で 12 から積む: 12.0 → 13.8 → 15.9 → 18.3
丸めると:                  12  →  14  →  16  →  18
実際の比率:                    1.167  1.143  1.125   ← 等比になっていない
```

小さい側では 1px の丸めが比率より支配的で、**どの比率を選んでも 12/14/16/18 付近に落ちる**。等比が意味を持つのは 24px より上だけ。実在のシステムも同様で、Tailwind のデフォルトは比率 1.111〜1.25 とばらつき、Material 3 は5役割×3サイズの決め打ち、HTML のデフォルト見出しも 1.17〜1.333 とバラバラ。**単一比率を厳密に守っているシステムはほぼ無い**。

### wixdex 実測との照合

| 実測サイズ | 使用回数 | スケール |
|---|---|---|
| 14px | **87** | ある |
| 12px | **35** | ある |
| 18px | 12 | **無い**（→ 16 か 20 に寄せる） |
| 16px | 7 | ある |
| 30px | 5 | 無い（→ 28 か 32） |
| 24px | 4 | ある |
| 20px | 4 | ある |

### ★18px を入れない（決定）

実測3位（12回）だが**採らない**。しろさまの判断:「**Tailwind にあったってだけだしね、18の理由**」。実際、wixdex の 18px は12回すべて `text-lg` の使用であり、設計上の必然ではなかった。段を増やさない縛りを優先する。

## §4 ウェイトと階層

```
400  500  700
```

★**2026-08-20 に 600 を廃止して3段にした。** Zen Maru Gothic は 300/400/500/700/900 で
**600 を持たない**。600 指定は 700 で描画され、フォールバックフォントでは 600/700 が
分かれるため環境で見た目が割れていた。実測の「semibold の見出し」は 700 が引き受ける
（Zen Maru Gothic 上では見た目は変わらない ―― もともと 700 で描画されていたため）。

### 実測 — 見出しはサイズでなくウェイトで作られていた

サイズ×ウェイトの組み合わせ回数:

| 組み合わせ | wixdex | Mado |
|---|---|---|
| **14px + semibold(600)** | **9** | 7 |
| **14px + medium(500)** | 6 | **8** |
| 20px + bold(700) | 4 | 3 |
| 24px + bold(700) | 4 | **7** |
| 18px + semibold/bold | 6 | – |

**最頻出の見出しは「14px のまま太くする」**。サイズを上げるのは大きい見出しだけ。両プロダクトで同じ構造だった。

HTML のデフォルトも同じで、`h4` は本文と同じ 16px、`h5`(13.3px) と `h6`(10.7px) は**本文より小さい**。それでも見出しとして機能するのは全部 bold だから。

## §5 役割の割り当て

**スケールは1つ。UI と長文で「どの段を本文にするか」だけが違う**（＝分けていない）。

### UI（アンカー 14px）

| 役割 | サイズ | ウェイト |
|---|---|---|
| `h1` | 20 | 700 |
| `h2` | 16 | 700 |
| `h3` | **14** | **700** |
| `p` | 14 | 400 |
| `small` | 12 | 400 |

### 長文（アンカー 16px）

| 役割 | サイズ | ウェイト | 追加 |
|---|---|---|---|
| `h1` | 28 | 700 | |
| `h2` | 24 | 700 | |
| `h3` | 20 | 700 | |
| `h4` | **16** | **700** | 本文と同サイズ |
| `h5` | 16 | 500 | |
| `h6` | **14** | 700 | 14 という大きさ自体がしるし |
| `p` | 16 | 400 | |
| `small` | 14 | 400 | |

★階層のしるしは**左の帯**が担う（`ui/prose.css`。h2〜h5 に太さ違いでぶら下がる）。
当初ここにあった「h5/h6 の字下げする左罫」は帯と二重になるため 2026-08-20 に外した。

**32px は「記事の外側」用**（ブログのヒーロー見出しなど）に予備として残す。

### ★h4〜h6 をサイズで作らない理由

UI では `h4` 以下はほぼ使われない（実測: wixdex h4=2回 / h5,h6=0回、Mado h4=2回 / h5,h6=0回）。しかし**長文では普通に出る**ので、段を増やさずに階層を表現する必要がある。

- `h4` … 本文と同サイズ + ウェイト
- `h5`/`h6` … ウェイト + **左の帯**（`ui/prose.css`）

これで **6階層が4つのサイズ + 3つのウェイト（400/500/700）**で取れる。

★一度「UI では h4 以下は使わないから潰す」と設計しかけたが、しろさまの指摘で撤回した:「**ブログとか規約とかに使うことあるよね？ wixdex ばかりに縛られるのはこのテーマを作る意義を見失ってる**」。適用範囲を wixdex に狭めていたのが誤りだった。

## §6 行間

**すべて4の倍数**。長文は UI に **+4px** するだけ。

| サイズ | UI 行間 | 比率 | 長文 行間 | 比率 |
|---|---|---|---|---|
| 12 | 16 | 1.333 | 20 | 1.667 |
| 14 | 20 | 1.429 | 24 | 1.714 |
| 16 | 24 | 1.500 | 28 | 1.750 |
| 20 | 28 | 1.400 | 32 | 1.600 |
| 24 | 32 | 1.333 | 36 | 1.500 |
| 28 | 32 | 1.143 | 36 | 1.286 |
| 32 | 36 | 1.125 | 40 | 1.250 |

- **UI 側の 12/14/16/20/24 は Tailwind のデフォルトと完全一致**。Tailwind のデフォルト行間はすべて4の倍数で、意図的にグリッドへ乗せてある
- wixdex は `leading-*` をほぼ指定しておらず（＝デフォルトのまま）、結果的にこの値を使っていた
- Mado は `leading-relaxed`(1.625) を21箇所で使用 → 長文側の値に近い
- **大きいサイズで比率が下がるのは正しい挙動**。見出しは1〜2行で終わるため、行間が広いとバラける
- ★**「+4px」を当てるのは本文（`p` / `small` / リスト）だけ**。見出しは長文の中でも UI の行間のまま
  （上の理由と同じ。`ui/prose.css` と Typography ページはこの規則で揃えてある）

## §7 余白（★未確定）

実測値と方針のみ。確定は wixdex 適用時。

| | wixdex（実測中央値） | Mado（実測中央値） |
|---|---|---|
| padding | **8px** | **20px** |
| gap | 8px | 8px |

**gap は両者一致、padding だけ 2.5倍違う**。しろさまが「wixdex はカツカツ」と感じていたものの実体は、**文字サイズではなく padding と行間**だった（文字サイズは両プロダクトともほぼ同じ分布）。

暫定案:

```
compact（UI）        縦 8px  / 横 16px
comfortable（長文）   縦 20px / 横 24px
gap                  8px（共通）
```

## §8 密度の軸

行間・padding は「UI か長文か」で決まる。**プロダクトごとに選ぶ軸ではなく、用途で自動的に決まる**。

```
UI      アンカー 14px / 行間は §6 の UI 列 / padding compact
長文    アンカー 16px / 行間は §6 の +4px 列 / padding comfortable
```

wixdex は `marked` + `@tailwindcss/typography`(prose) で markdown をレンダリングしており、**UI と長文が同一プロダクト内に共存している**（デッキのメモ）。この2軸はそこで実際に必要になる。
