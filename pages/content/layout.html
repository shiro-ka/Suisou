Layout

並び。モードを 1 つ書いた時点で display と gap: 8px（space-2）が入る。 すきまは焼き込んである —— Suisou の間合いは毎回選ぶものではない。 値は空白区切りで重ねるので、属性はいくつ語を並べても1つ。 row や grow という汎用の名前を class として 世界から奪わないために、並びは属性の中の語にしてある。

既定 —— モードを書かなければ何も起きない

★2026-09-09 に変えた。それまでは属性を付けた時点で display: flex が入っていた。そのせいで 子側の語（grow）だけを 書いた要素まで flex の行になっていた。

data-suisou-layout="grow" だけ書いた <main> が 横並びの入れ物になり、ページが 4071px に伸びた。 share（当時の語）を button-group に足したら 8px の隙間が割り込んだ。どちらも実際の現場で起きている。

「モードを必ず 1 つ添える」という決まりを破った側の落ち度ではあるが、 破ったときに黙って別物になるのが仕組みの落ち度。 display を敷くのをモードの仕事に移した。

★すきまは --suisou-gap を経由する。gap-N の規則は モードより前に書かれているので、モード側で gap を直に書くと gap-N が順序で負ける。

★基底の宣言も :where() で包んで詳細度を 0 にしてある （2026-09-17）。子の既定（flex: none）と同じ扱いで、 gap-N も現場の規則も順序に頼らず必ず勝てる。 それまで基底だけ包まれておらず、2行で扱いが分かれていた。

子は既定で動かない（flex: none）。 flex 本来の既定は 0 1 auto ＝「伸びないが縮む」で、これが驚きの元になる —— width: 200px と書いても守られないし、stack scroll-y の中身が スクロールせずに潰れる。Suisou は「言われたことしかしない」を既定にして、 動くものには grow と名指しさせる。 おかげで flex の中で動く要素は目で数えられる。

スクロールバー

色と太さは根（data-suisou-body）が持ち、継承で全部に届く。 つまみは line-strong、溝は透明。線1本だけが見える。 標準の scrollbar-width / scrollbar-color だけを使い、 ::-webkit-scrollbar は書かない —— あちらは標準化されたことがなく、 同じことが標準側でできるようになった。

幅は予約する（scrollbar-gutter: stable both-edges）。 scroll-y に焼き込んであるので、現場が書く必要はない。

stable だけだと溝が右にしか空かず、左右の余白が食い違う —— 溝は padding の外側に足され、バーが無いときは padding の延長として塗られるため。 both-edges は反対側にも同じ溝を作るので対称になる。 代償は溝2本ぶん中身が痩せること。ただしオーバーレイ型のスクロールバー （macOS / iOS の既定）では溝が作られないので、痩せるのは クラシック型の環境だけで、そこでは元々バーが出たときに痩せていた。

★「右の padding を溝の分だけ減らす」という手は採らない。 溝の実寸はブラウザ・OS・設定で違い、CSS から知る手段が無い。 JS で測れば正確だが、JS を要求する部品は作らないのが Suisou の割り切り。 決め打ちにすると、溝が作られないオーバーレイ型の環境で 右だけ狭くなって対称が壊れる。 both-edges は溝の幅を一度も知らずに済む —— 答えを持たず、条件だけブラウザに渡す。

★横スクロール（scroll-x）には効かない。 scrollbar-gutter が制御できるのは左右の端だけで、 上下の端は仕様の範囲外（CSS Overflow 3）。 横バーの出入りで高さが動くのは、現時点の CSS では止められない。

★scroll-x に余白の補正を焼き込むことはしない。 バー幅ぶんの padding-bottom を当て勘で引く手はあるが、 合うのは「クラシック型のバーが実際に出ている」ときだけで、 出ていないときとオーバーレイ型の環境では下だけ狭くなる。 そもそも layout は padding を持たない —— 面の内側の余白は tray の担当で、 tray.css は layout.css より後に読まれるので、 書いても上書きされる。穴は塞がずに空けておき、要る現場が面の側で調整する。

必ず対で使う。「狭いときは三本線、広いときはリンクの帯」 「狭いときは上の帯、広いときは脇」—— 2 現場で実測 17 箇所、 全部この形だった。

★★これは語彙の穴であると同時に罠を 1 つ消す。 [data-suisou-layout] { display: flex } は無条件なので、 現場が Tailwind の hidden を併記しても黙って殺される （Tailwind v4 は @layer utilities の中にあり、 レイヤ無しの Suisou に詳細度でも順序でも勝てない）。 Suisou 側に語があれば同じレイヤの中で素直に効く。

★記法は「段 + 記号 + 語」で、記号は不等号として読む。 段が左の被演算子、画面幅が右 —— s>none は 「md が画面より大きい」＝ 768px 未満で消える。境界の 768px ちょうどは s: 側に入る。

★ui/show.css は layout.css より後に読む。 詳細度は同じ [attr] なので、display: none を勝たせるのは順序だけ。 index.html の並びが契約の一部になる。
