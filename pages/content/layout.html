Layout

並び。モードを 1 つ書いた時点で display と gap: 8px（space-2）が入る。 すきまは焼き込んである —— Suisou の間合いは毎回選ぶものではない。 値は空白区切りで重ねるので、属性はいくつ語を並べても1つ。 row や grow という汎用の名前を class として 世界から奪わないために、並びは属性の中の語にしてある。

既定 —— モードを書かなければ何も起きない

★2026-09-09 に変えた。それまでは属性を付けた時点で display: flex が入っていた。そのせいで 子側の語（grow / share / hold）だけを 書いた要素まで flex の行になっていた。

data-suisou-layout="grow" だけ書いた <main> が 横並びの入れ物になり、ページが 4071px に伸びた。 share を button-group に足したら 8px の隙間が割り込んだ。どちらも実際の現場で起きている。

「モードを必ず 1 つ添える」という決まりを破った側の落ち度ではあるが、 破ったときに黙って別物になるのが仕組みの落ち度。 display を敷くのをモードの仕事に移した。

★すきまは --suisou-gap を経由する。gap-N の規則は モードより前に書かれているので、モード側で gap を直に書くと gap-N が順序で負ける。

子は既定で動かない（flex: none）。 flex 本来の既定は 0 1 auto ＝「伸びないが縮む」で、これが驚きの元になる —— width: 200px と書いても守られないし、stack scroll の中身が スクロールせずに潰れる。Suisou は「言われたことしかしない」を既定にして、 動くものには grow と名指しさせる。 おかげで flex の中で動く要素は目で数えられる。

★tools/lint_css.py が同時指定を検査する。 モードの一覧は layout.css から導いている —— 「display か flex-direction を敷いているか」で判定する。 手で持っていたときに even を足し忘れて "stack even" が素通りしたので、真実の源泉を1つにした。

寄せ —— 主軸方向

justify-content は主軸方向の「余った空間の配り方」で、 子の置き方ではない。align-items（交差軸）と混ざりやすいが、 向きで意味が入れ替わる —— row なら横、stack なら縦に効く。

★子に grow が1つでもあると効かなくなる。 grow が余りを全部取ってしまい、配るものが残らないため。 「なぜか効かない」の大半はこれ。

★middle は主軸、center は交差軸。 軸が違うだけで、どちらも「中央」。

row middle は横に並べて横方向の中央、 stack center は縦に積んで横方向の中央。 いちばん多いのは stack center（空表示、ランディングの節）。

スクロールバー

色と太さは根（data-suisou-body）が持ち、継承で全部に届く。 つまみは line-strong、溝は透明。線1本だけが見える。 標準の scrollbar-width / scrollbar-color だけを使い、 ::-webkit-scrollbar は書かない —— あちらは標準化されたことがなく、 同じことが標準側でできるようになった。

骨格を組む —— frame

画面の骨格は frame が持つ。区画を親がまとめて決め、 子は「自分がどの区画か」しか言わない。 flex では2次元が作れないので、右側をまとめるためだけの空箱が要った。それが消える。

区画の名前は Suisou が持つ（aside / head / body / foot）。 現場が名前を発明すると channel-list のような今回だけの語になり、 配れなくなるため。

画面幅で出し分ける —— data-suisou-show

必ず対で使う。「狭いときは三本線、広いときはリンクの帯」 「狭いときは上の帯、広いときは脇」—— 2 現場で実測 17 箇所、 全部この形だった。

★★これは語彙の穴であると同時に罠を 1 つ消す。 [data-suisou-layout] { display: flex } は無条件なので、 現場が Tailwind の hidden を併記しても黙って殺される （Tailwind v4 は @layer utilities の中にあり、 レイヤ無しの Suisou に詳細度でも順序でも勝てない）。 Suisou 側に語があれば同じレイヤの中で素直に効く。
