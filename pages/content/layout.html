Layout

並び。属性を付けた時点で display: flex と gap: 8px（space-2）が入る。 すきまは焼き込んである —— Suisou の間合いは毎回選ぶものではない。 値は空白区切りで重ねるので、属性はいくつ語を並べても1つ。 row や grow という汎用の名前を class として 世界から奪わないために、並びは属性の中の語にしてある。

既定

値を1つも書かなくても flex と gap は効く。向きは横、子は高さいっぱいに伸びる —— flex の初期値そのままなので、ここに名前は要らない。

ただし子は既定で動かない（flex: none）。 flex 本来の既定は 0 1 auto ＝「伸びないが縮む」で、これが驚きの元になる —— width: 200px と書いても守られないし、stack scroll の中身が スクロールせずに潰れる。Suisou は「言われたことしかしない」を既定にして、 動くものには grow と名指しさせる。 おかげで flex の中で動く要素は目で数えられる。

寄せ —— 主軸方向

justify-content は主軸方向の「余った空間の配り方」で、 子の置き方ではない。align-items（交差軸）と混ざりやすいが、 向きで意味が入れ替わる —— row なら横、stack なら縦に効く。

★子に grow が1つでもあると効かなくなる。 grow が余りを全部取ってしまい、配るものが残らないため。 「なぜか効かない」の大半はこれ。

スクロールバー

色と太さは根（data-suisou-root）が持ち、継承で全部に届く。 つまみは line-strong、溝は透明。線1本だけが見える。 標準の scrollbar-width / scrollbar-color だけを使い、 ::-webkit-scrollbar は書かない —— あちらは標準化されたことがなく、 同じことが標準側でできるようになった。

幅の予約（scrollbar-gutter）はしない。 バーが出た瞬間の幅の飛びは止まるが、代わりに溝がずっと居座る。 stable は右だけに空くので左右の余白が食い違い、 both-edges は両側に空く分だけ中身が痩せる。 どちらも「常に変」で、バーが出るときだけ 10px 動く方がまだ普通に見えた。

骨格を組む —— frame

画面の骨格は frame が持つ。区画を親がまとめて決め、 子は「自分がどの区画か」しか言わない。 flex では2次元が作れないので、右側をまとめるためだけの空箱が要った。それが消える。

区画の名前は Suisou が持つ（aside / head / body / foot）。 現場が名前を発明すると channel-list のような今回だけの語になり、 配れなくなるため。
