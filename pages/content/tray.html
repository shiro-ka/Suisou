Surface

面。値で選ぶ —— 面は階段（bg < panel < item < overlay）という 閉じた集合なので、属性は1つで値を切り替える。部品（media や btn）はこれから増えるので属性そのものが名前になる。 形が違えば層が違うと分かる。 平らな容れ物だけを引き受け、影は持たない。浮くものは overlay として後で足す。

値

data-suisou-tray="panel"
面 + 罫。既定
罫なし。面だけで区切る
段を上げず、罫だけで囲う
段（必須・1つ）面使う場面
panel--suisou-panel いちばん普通の容れ物。地べたに敷いて、その上にモノを載せる
item--suisou-item 1段手前。panel の中に置く入れ子の容れ物

★階段は Suisou の言葉。 背景（bg）があって、その上に入れ物（panel）を配置して、 その中に UI のモノ（item）を入れる。 item の中に item は想定していない —— そうしたくなったら UI 側に改善の余地があるという合図。だから階段はこの3段で終わり。

装飾（任意）効果
bd-none罫を消す（border-color: transparent）
bd-dash罫を破線に（border-style: dashed）
bg-none背景を消す（background: transparent）
装飾
既定 —— 罫は実線、余白 8px。段は持たない
bd-dash —— 破線。まだ何も無い場所に
bd-none —— 罫なし。面だけで区切る
bg-none —— 背景なし。罫だけで囲う

値は空白区切りで重ねる（"panel bd-dash"）。 段を書かずに装飾だけ書いても意味が通らない —— 面だと宣言しておいてどの段か言っていないため。 tools/lint_css.py が段をちょうど1つ持っているか検査する （drawer は段を持たない独立した語なので除く）。

★属性だけでは何も起きない。 border / border-radius / padding は段の語が持つ。 値を書かせる設計にしてある。

overlay —— 浮くもの

モーダル・ポップオーバー・ドロップダウン。 他の面と違い「下地が読めない」のが唯一の特徴なので、 明度差だけに頼らず罫を line-strong に上げる。 line-strong on overlay は PAIRS で 3.0 以上を検証済み。

開閉に JS を使っていない（popovertarget 属性だけ）。出入りも animate する
drawer start —— 行頭から出る

ナビゲーションのドロワーは慣習的に左から出る。論理方向の名前なので RTL でも通る。Mado の要求で足した（2026-08-22）。

drawer —— 端に寄せて浮く

ハンバーガーの中身・モバイルのメニュー。出入りはフェードではなく端からの滑り。 ESC でも外側クリックでも閉じる —— ぜんぶブラウザの仕事で、JS は1行も無い。

overlay の面

後ろが scrim で塞がれている。罫は line-strong。

出入りは --suisou-motion（200ms）でふわっとさせている。 JS は使っていない —— display と overlay を allow-discrete で繋ぎ、 @starting-style で「開く直前の姿」を与えるのが定石。 未対応のブラウザでは単に animate しないだけで壊れない。
膜（scrim）は中身より少し速く消える —— 閉じたことが先に伝わる。

★影は持たない。「線形デザインだから」ではなく、 ダーク専用では影が機能しないため。 影は下地を暗くする技法だが、Suisou の下地は既に暗いので暗くする余地が無い。

やり方panel(L22) の上での輝度比判定
Tailwind の shadow-xl（黒 α0.10）1.02 何も起きていない
一番濃い scrim（α0.72）1.14 Suisou の一番緩い基準（装飾罫 1.5）にも届かない
白い光 α0.153.45効く。ただし下を見る
罫を line-strong に3.10 採用。白い光とほぼ同じ強さ

暗い側で効くのは光の方で、白いグロウは理屈では正しい。 ただ line-strong を罫に回すとほぼ同じ強さになる —— つまりSuisou の罫は、ぼかしていない白い光。 足すと同じものが二重になって輪郭が濁るので足さない。 Linear などが内側に白い光を入れるのは罫が極端に薄いからで、 罫を 3:1 で引く Suisou には代用品が要らない。

例外は画像の上に浮くもの（下地の明るさが読めない）。 白い下地なら scrim は 3.18 で効く。 ただし overlay の仕事ではないので、3回書いてから足す。

入れ子

内側は明示的に1段手前（item）を指定する。自動では上げない —— 値で書いてあるものを裏で書き換えられると読めなくなるため。 仕様の「モーダル内の入力欄がモーダルより明るくなる」順序は、階段の順に 値を選べば守れる。

panel の中に item

内側 — item。1段手前
内側 — outline。面を持たない

中身の並べ方は持たない

Panel が持つのは見た目だけ。並べ方は class のユーティリティが担当する。 territory を分けているので、適用先が Tailwind でも取り合いにならない。

区切りの罫 —— data-suisou-rule

Suisou は面ではなく線で区切る体系なのに、 その線の語が長いあいだ無かった（2026-09-09 に追加）。 2 現場で border-<辺>: 1px solid var(--suisou-line-weak) を 17 箇所手書きしていた —— うち片方は .rule という同じ 3 行を4 つのファイルに複製していた。 語が無いと現場が各自で発明する。

★row="ruled" とは別物。あちらは一覧の行と行の間の罫で、 こちらは構造の縁（帯の下・脚の上・脇と本文の間）。用途が重ならない。

★色は書かない。--suisou-line-weak を読むだけなので、 面や行の状態に応じて文脈が値を差し替える。 罫の側は「どの面の上に載っているか」を知らなくていい。

★辺は論理プロパティ（block-start / block-end / inline-end）。start は持たない —— 実測で 0 件で、左に立てる 1 本は quote の役目だから。
