Prose

長文。markdown が吐いた素の HTML に属性を書けないので、 包む側に1つだけ付けて中で割り当てる。

★Suisou で唯一「素の要素に直接当てる」場所。 base.css の「要素セレクタは使わない」を破るが、 data-suisou-prose の内側に閉じているので適用先には漏れない。 破っていい場所を1つだけ用意して封じ込める、という形。

新しい見た目を発明していない

リンク・コード・引用・箇条書き・表は、それぞれの部品ファイルが [data-suisou-prose] :where(…) を自分のセレクタに並べている。 値を2箇所に書くとズレるので、prose.css 側では触らない。 このファイルが持つのは「大きさの割り当て」と「縦のリズム」だけ。

data-suisou-prose

面の階段

Suisou の面は4段ある。深いほど光が届かず、面の色が薄くなる。 地べたに置くのはヘッダの要素だけで、 モノは panel に入れる。

段の決まり方

値は tools/solve.py が制約から解いている。 手で置いた色は1つも無い。

  • bg — 地べた。ヘッダだけが載る
  • panel — いちばん普通の容れ物
    • 入れ子にするときは item を明示する
    • 自動では上げない
  • overlay — 浮くもの。罫が強くなる

影は使わない。ダーク専用では下地を暗くする余地が無いため。

コードで書くと

[data-suisou-surface~="panel"] { background: var(--suisou-panel); }
左罫のつく見出し

h5 と h6 はサイズを増やさず、ウェイトと左罫で階層を作る。 段が7つしかないので、6段の見出しに1段ずつ割り当てると本文と衝突する。

縦のリズム

★見出しは「前を広く、後ろを詰める」。 前の話題から離し、次の内容に近づける。タイポの定石で、 段を増やす前にまずこれを当てる。 おかげで space-4（24px 相当）までで足りていて、 新しい段が要らなかった。

短い方 —— tight

panel の中に入るメモ。wixdex のデッキメモがこの形 （Tailwind の prose-sm 相当）。本文を1段落とし、リズムも1段詰める。

data-suisou-prose="tight"
