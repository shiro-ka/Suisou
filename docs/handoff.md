## ★このリポジトリの掟

### 1. 色を決めるのは `tools/solve.py` だけ

色の値をどこにも手で書かない。CSS にも仕様書にも書かない。

```
python3 tools/solve.py          # 生成（palette.data.js と spec-tables.md）
python3 tools/solve.py --check  # 検証のみ。破綻があれば exit 1
```

数値の表は `tools/spec-tables.md`（生成物）にある。**`docs/palette-spec.md` は散文と判断の理由だけを持ち、表を持たない。**

理由: 設計中、「ツール(JS) / Python / 仕様書の表」の3つが同じ数値を主張して同期が手作業だった結果、**色域チェック漏れ・トークン数の誤記・検証ペアの欠落**という3つのバグを出した。真実の源泉は1つにする。

### 2. 守るものと譲るもの

```
絶対に守る … 色域内 / コントラスト基準 / ΔE フロア
目標（譲る）… L 階段の値
```

「L 階段は全テーマ共通で固定」は**維持できない約束**だった（同じ L94 でも面C と H によって色域に入ったり入らなかったりする）。守れない約束を持つと、破っても気づけない。制約を先に置き、L は最小限だけ譲る。

### 3. 設計の入力は4つだけ

```
[1] L 階段（2系統: dark / dim）
[2] テーマ … H / 面C / アクセント強さ の3つ
[3] アクセント … H だけ
[4] 意味色 … H と L
```

残りは全部導出。人が値を持たない。

### 4. しろさまとの進め方

- **しろさまはスライダーを触らない。** こちらが制約を解いてパレットを提出し、しろさまは実物を見て「紫もうちょい明るく」のような指示を出す。**それを数値に翻訳するのはこちらの仕事**
- **未検証で自信満々が最大の地雷。** 数値を出すときは必ず計算して確かめる。「たぶん」で断定しない
- **実物判定はしろさまの言葉が正。** ΔE フロアが 0.055 なのは、実物を見て「0.058 でも区別できる」と判定したから
- **wixdex だけを見て設計しない。** 適用先にはブログ・規約などの長文も含まれる。一度 h4〜h6 を「UI では使わないから」と潰しかけて、指摘で撤回した

## 決まっていること

- **色** … 4テーマ × 9アクセント。36通り中33が使用可、構造的破綻0件。詳細は `docs/palette-spec.md`
- **タイポ** … サイズ `12/14/16/20/24/28/32`、行間は4の倍数の2系統、ウェイト4段。詳細は `docs/type-spec.md`
- **線形デザイン** … 塗らない（CTA すらアウトライン）。美学であると同時に、テーマ切替を技術的に成立させている柱
- **影は「実際に浮くもの」だけ**（モーダル・ポップアップ）。面の分離は border が担保する
- **ダーク専用**。純粋なライトテーマは作らない。ライト志向のユーザーには `dim` 系統（明るめの階段）を投げる

## ★保留（これから決める）

### 命名

**確定しているのは `Suisou`（システム名）だけ。**

- ~~**テーマ名**~~ … ★**確定（2026-08-18）**。水域にした。深いほど光が届かず面の色が薄くなる順で
  `hadal`（超深海層）/ `trench`（海溝）/ `fjord`（峡湾）/ `shoal`（浅瀬）。
  `hadal` は Akuarium から継承。`fjord` は旧 `nord-ish` で、Nord 由来を残したまま水域名にした。
  これで階段名 `dim` とテーマ名の衝突も解消した
- **アクセント名** … 海の生き物にする方針（coral / turtle など）。現在の `orange / lime / teal / cyan / blue / indigo / purple / magenta / pink` も**仮名**

★このリポジトリには前身の **Akuarium** が入っており、**既に命名体系がある**。

```css
--blackish-h: 222     /* 暗いテーマ */
--hadal-h: 220        /* 超深海層 */
--jellyghoti-h: 196   /* アクセント。jellyfish + ghoti の言葉遊び */
```

つまり「テーマ = 水域、アクセント = 海の生き物」は今回思いついた方針ではなく、**Akuarium で既に実装されていた設計**。命名を決めるときはここから引き継げる。

## 既存の Akuarium をどうするか（最初の分岐）

このリポジトリには Akuarium の実体がある。

```
akuarium-theme/   theme-var / theme-class / primary-var / primary-class   （HSL ベース）
akuarium-ui/      layout（header/main/footer/container/box/items/wrapper）
                  text/heading  utility（margin/height/flex/font-size/justify…）
.github/workflows/ build_akuarium-theme.yml / build_akuarium-ui.yml       （ビルド済み）
```

発想の骨格は今回の設計と同じ（CSS変数でテーマを定義し、クラスで適用する）。違うのは**色空間（HSL → OKLCH）**と、**値を制約から解くかどうか**。

- **A: 既存を土台に、色だけ OKLCH に差し替える** … レイアウトとユーティリティが活きる。ビルドも動いている
- **B: Suisou として作り直し、Akuarium は参考にする** … 命名（`hadal` / `jellyghoti`）だけ引き継ぐ
- **C: 一旦そのまま並置** … 統合は後で考える

**未決。** ここを決めるのが最初の作業になる。

## 次の工事

1. **`solve.py --check` を CI に入れる**（GitHub Actions）。破綻が混入した瞬間に落ちる。既存の workflow が2本あるので、そこに足す形
2. **APCA の advisory 並走** … WCAG 2 と判定が割れたペアだけを実機確認リストとして出す。`line-weak`(1.51:1) と `error`(4.59:1) が真っ先に載るはず
3. **CVD シミュレーション** … Oklab の ΔE は色覚特性をモデル化していない。2型色覚では `lime`/`teal` と `success`、`orange`/`pink` と `error` が危険側に寄る。**しろさまの実物判定はこの穴を埋めない**
4. **wixdex への適用** … 現状 gray と zinc が二重化し色クラスが69種類ある。これを20トークンに畳む
